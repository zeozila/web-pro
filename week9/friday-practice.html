Week 9 Friday — GitHub Pages & Deployment Practice

Practice publishing a static website, checking a missing-page response, and creating a custom 404 page.

Custom 404 page added: Preview the portfolio's 404 page.

Exercise 1: Enable GitHub Pages

Goal: Publish a repository as a live website.

  1. Open your repository on GitHub and select Settings, then Pages.
  2. Under Build and deployment, choose Deploy from a branch.
  3. Select the main branch and /(root) folder, then save.
  4. Wait for the deployment to finish and open the published URL shown in Pages settings.
  5. This portfolio is published at https://zeozila.github.io/web-pro/; verify that your own Pages settings show the expected source and deployment status.

Exercise 2: Check a 404 page

Goal: See what visitors get when they request a page that does not exist.

  1. Open a deliberately missing page on this site.
  2. Observe the not-found page and note how it helps visitors return to the portfolio.

Exercise 3: Create a custom 404 page

Goal: Add a friendly not-found page to the site and deploy it.

  1. A custom 404.html has been added at the repository root, beside index.html.
  2. It explains the error and includes a link back to the portfolio.
  3. Preview it directly: Open 404.html.
  4. After GitHub Pages deploys the latest commit, test the missing-page link above to confirm the published 404 behavior.

Deployment note: The repository files are committed, but confirm in GitHub Pages that this latest revision has finished deploying before treating the live-site check as complete.
